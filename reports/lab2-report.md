# Звіт до лабораторної роботи №2

**Тема:** Аутентифікація, авторизація та розширений функціонал

### Мета роботи

Розширити REST API системи моніторингу фізичної активності та здоров'я шляхом реалізації механізмів аутентифікації й авторизації, захисту даних користувачів, розширеної роботи з ресурсами та завантаження файлів.

### 1. Реалізація аутентифікації

У проєкті реалізовано:
- реєстрацію користувачів із перевіркою обов'язкових полів, формату електронної пошти та довжини пароля;
- хешування паролів за допомогою Argon2id;
- вхід користувача з перевіркою облікових даних;
- створення JWT access-токенів;
- створення refresh-токенів із терміном дії;
- оновлення access-токенів із ротацією refresh-токенів;
- відкликання refresh-токенів під час виходу із системи.

Refresh-токени зберігаються в базі даних у вигляді SHA-256 хешів.

### 2. Авторизація та контроль доступу

Створено middleware для перевірки JWT-токенів і визначення ролі користувача.

Реалізовано дві ролі:
- USER — звичайний користувач;
- ADMIN — адміністратор.

Доступ до ресурсів обмежено відповідно до ролі та власника даних. Звичайний користувач може працювати зі своїм профілем та власними записами активності. Адміністратор має розширені права доступу.

### 3. Розширена робота з активностями

Розширено контролер активностей. Реалізовано:
- пагінацію результатів;
- обмеження кількості записів на сторінці;
- фільтрацію за типом активності;
- пошук за текстом нотаток;
- фільтрацію за діапазоном дат;
- перевірку ідентифікаторів і прав доступу.

### 4. Завантаження та керування файлами

Реалізовано завантаження файлів за допомогою Multer.

Підтримуються формати JPG, JPEG, PNG та PDF. Максимальний розмір файлу обмежено 5 МБ.

Для файлів реалізовано:
- перевірку MIME-типу та розширення;
- генерацію унікальних імен;
- збереження файлів у локальній директорії `uploads`;
- збереження метаданих у базі даних;
- отримання списку файлів;
- видалення файлів із файлового сховища та бази даних.

Доступ до файлів обмежено відповідно до користувача та його ролі.

### 5. Оновлення структури бази даних

До схеми Prisma додано дві моделі:

- `File` — зберігає інформацію про завантажені файли: власника, початкову назву, MIME-тип, розмір, шлях і дату завантаження.
- `RefreshToken` — зберігає хеш refresh-токена, власника, термін дії, дату створення та дату відкликання.

Зміни застосовано до бази даних за допомогою міграції Prisma.

### 6. Документація API

Підключено Swagger через `swagger-jsdoc` та `swagger-ui-express`.

Документація доступна за адресою:

`http://localhost:3000/api-docs`

Додано опис маршрутів аутентифікації, активностей і роботи з файлами. Налаштовано схему Bearer JWT для авторизованих запитів.

### 7. Захист API

Для підвищення безпеки застосовано:
- Helmet для встановлення захисних HTTP-заголовків;
- express-rate-limit для обмеження частоти запитів до маршрутів аутентифікації;
- перевірку JWT-токенів;
- перевірку ролей і прав власності;
- валідацію вхідних даних.

Для маршрутів `/api/auth` встановлено обмеження у 100 запитів протягом 15 хвилин.

### 8. Тестування

Для автоматизованого тестування використано Node.js Test Runner та Supertest.

Реалізовано перевірки:
1. Відхилення реєстрації з порожніми даними.
2. Відхилення реєстрації з некоректною електронною поштою.
3. Відхилення входу без пароля.
4. Наявність захисних HTTP-заголовків Helmet.

Результат виконання `npm test`:

- Усього тестів: 4.
- Успішно пройшло: 4.
- Помилок: 0.

Додатково вручну перевірено реєстрацію, вхід, оновлення та відкликання токенів, розмежування доступу користувачів, фільтрацію активностей, а також завантаження, перегляд і видалення файлів.

### Висновок

У ході лабораторної роботи розширено REST API системи моніторингу фізичної активності та здоров'я. Реалізовано аутентифікацію на основі JWT, хешування паролів Argon2id, механізми авторизації за ролями, захист ресурсів користувачів, пагінацію та фільтрацію активностей, завантаження файлів і документацію Swagger.

Також додано захисні HTTP-заголовки, обмеження частоти запитів і автоматизовані тести. Працездатність реалізованого функціоналу перевірено автоматизованими та ручними тестами.
