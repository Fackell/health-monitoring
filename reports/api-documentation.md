# Документація API — Health Monitoring

## 1. Загальна інформація

**Назва:** Health Monitoring API  
**Версія:** 1.0.0  
**Технології:** Node.js, Express.js, PostgreSQL, Prisma ORM.

**Базова адреса:** `http://localhost:3000`

API призначений для керування користувачами та їхньою фізичною активністю.

## 2. Перевірка працездатності

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/` | Головна інформація про API |
| GET | `/api/health` | Перевірка працездатності сервера |
| GET | `/api/health/database` | Перевірка підключення до БД |

## 3. Користувачі

Базовий маршрут: `/api/users`

| Метод | Маршрут | Призначення |
|---|---|---|
| POST | `/api/users` | Створення користувача |
| GET | `/api/users` | Отримання списку користувачів |
| GET | `/api/users/:id` | Отримання користувача за ID |
| PUT | `/api/users/:id` | Оновлення користувача |
| DELETE | `/api/users/:id` | Видалення користувача |

### Приклад створення користувача

**POST** `/api/users`

```json
{
  "email": "user@example.com",
  "password": "Password123",
  "fullName": "Test User"
}
```

Пароль повинен містити щонайменше 8 символів. Електронна адреса має бути унікальною.

## 4. Фізична активність

Базовий маршрут: `/api/activities`

| Метод | Маршрут | Призначення |
|---|---|---|
| POST | `/api/activities` | Створення запису активності |
| GET | `/api/activities` | Отримання списку активностей |
| GET | `/api/activities/:id` | Отримання активності за ID |
| PUT | `/api/activities/:id` | Оновлення активності |
| DELETE | `/api/activities/:id` | Видалення активності |

### Приклад створення активності

**POST** `/api/activities`

```json
{
  "userId": "54366ad7-16ef-4c0e-9038-0f1ca6e3d8cf",
  "type": "RUNNING",
  "durationMinutes": 30,
  "distanceKm": 5.2,
  "caloriesBurned": 350,
  "notes": "Ранкова пробіжка",
  "startedAt": "2026-11-15T08:00:00.000Z"
}
```

Доступні типи активності:

- `WALKING` — ходьба;
- `RUNNING` — біг;
- `CYCLING` — їзда на велосипеді;
- `SWIMMING` — плавання;
- `STRENGTH_TRAINING` — силове тренування;
- `OTHER` — інше.

Тривалість повинна бути додатним цілим числом. Відстань і кількість калорій є необов'язковими параметрами.

## 5. Формат відповідей

Успішна відповідь:

```json
{
  "status": "success",
  "data": {}
}
```

Відповідь із помилкою:

```json
{
  "status": "error",
  "message": "Опис помилки"
}
```

## 6. Основні HTTP-статуси

| Код | Значення |
|---|---|
| 200 | Запит успішно виконано |
| 201 | Ресурс успішно створено |
| 400 | Некоректні вхідні дані |
| 404 | Ресурс або маршрут не знайдено |
| 500 | Внутрішня помилка сервера |

## 7. Особливості реалізації

- Express.js використовується для створення HTTP-сервера та маршрутизації.
- Prisma ORM забезпечує взаємодію з PostgreSQL.
- bcryptjs використовується для хешування паролів.
- Вхідні дані перевіряються перед виконанням операцій із базою даних.
- Помилки обробляються контролерами та повертаються у форматі JSON.
- Налаштування підключення до бази даних зберігаються у змінних середовища.
