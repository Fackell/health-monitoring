# WebSocket API

## Загальна інформація

Для обміну даними в реальному часі сервер використовує Socket.IO 4. Socket.IO працює поверх власного протоколу обміну повідомленнями та не є взаємозамінним із нативним WebSocket API браузера.

Production endpoint:

`https://health-monitoring-grk9.onrender.com`

Локальний endpoint:

`http://localhost:3000`

## Автентифікація

Під час підключення клієнт повинен передати чинний access JWT у властивості `auth.token`.

Приклад клієнта:

```javascript
import { io } from "socket.io-client";

const socket = io("https://health-monitoring-grk9.onrender.com", {
  auth: {
    token: accessToken
  }
});

socket.on("connect", () => {
  console.log("Socket connected:", socket.id);
});

socket.on("connect_error", (error) => {
  console.error("Socket connection error:", error.message);
});
```

Сервер перевіряє токен через `verifyAccessToken`. Якщо токен відсутній або недійсний, підключення відхиляється з помилкою `unauthorized`.

Після успішної автентифікації сервер приєднує сокет до персональної кімнати:

`user:<userId>`

## Кімнати

Персональна кімната використовується для адресної доставки подій конкретному користувачу. Ідентифікатор користувача береться з перевіреного JWT, а не з довільного значення, переданого клієнтом.

У модулі також зареєстровані події `room:join` та `room:leave`. Не слід використовувати довільне приєднання до кімнат як механізм авторизації доступу до чужих даних.

## Події активностей

Сервер надсилає події в персональну кімнату користувача після відповідних операцій з активностями.

| Подія | Коли надсилається |
|---|---|
| `activity:created` | Після створення активності |
| `activity:updated` | Після оновлення активності |
| `activity:deleted` | Після видалення активності |

Приклад отримання подій:

```javascript
socket.on("activity:created", (activity) => {
  console.log("Created activity:", activity);
});

socket.on("activity:updated", (activity) => {
  console.log("Updated activity:", activity);
});

socket.on("activity:deleted", (activity) => {
  console.log("Deleted activity:", activity);
});
```

## Відключення та повторне підключення

Socket.IO підтримує механізм повторного підключення клієнта. Після відновлення з'єднання сервер повторно перевіряє переданий токен та приєднує клієнта до його персональної кімнати.

У поточній реалізації не зберігається історія WebSocket-подій для відновлення пропущених повідомлень. Щоб отримати актуальний стан після перепідключення, клієнт може повторно запросити дані через відповідні HTTP API.

Якщо access JWT завершив термін дії, клієнту потрібно отримати новий токен через механізм оновлення сесії та підключитися з ним.

## Обмеження поточної реалізації

- Події реального часу реалізовані для сутності активностей.
- Персональні кімнати формуються на основі JWT-користувача.
- Окреме сховище історії подій не реалізоване.
- Онлайн-статуси користувачів не реалізовані.
- Redis-адаптер та горизонтальне масштабування не налаштовані.
- Окремий rate limiting для WebSocket-подій не реалізований.
