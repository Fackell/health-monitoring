# Звіт до лабораторної роботи №4

## Тема

Реалізація React-проєкту для системи моніторингу фізичної активності та показників здоров'я.

## Мета роботи

Ознайомитися з розробкою клієнтської частини вебзастосунку з використанням React та TypeScript. Навчитися створювати проєкт за допомогою Vite, налаштовувати маршрутизацію, стилізацію, структуру компонентів, взаємодію з API та базові механізми обробки помилок.

## Завдання роботи

1. Створити React-проєкт із використанням TypeScript та Vite.
2. Налаштувати Tailwind CSS для стилізації інтерфейсу.
3. Налаштувати ESLint та Prettier для перевірки й форматування коду.
4. Підключити React Router та Axios.
5. Організувати структуру проєкту з розподілом компонентів, сторінок, сервісів, типів та допоміжних функцій.
6. Реалізувати повторно використовувані UI-компоненти.
7. Створити основні сторінки та компоненти макета вебзастосунку.
8. Забезпечити адаптивність інтерфейсу.
9. Налаштувати змінні середовища та типізацію даних API.
10. Реалізувати Axios interceptors та Error Boundary.
11. Налаштувати псевдонім імпорту `@/`.
12. Реалізувати допоміжні функції форматування та перемикання теми оформлення.
13. Перевірити коректність роботи та виконати production-збірку проєкту.

## 1. Використані технології

Під час виконання лабораторної роботи було використано такі інструменти та технології:

| Технологія | Призначення |
|---|---|
| React | Створення користувацького інтерфейсу |
| TypeScript | Статична типізація коду |
| Vite | Створення та збирання проєкту |
| Tailwind CSS | Стилізація та адаптивна верстка |
| React Router | Маршрутизація між сторінками |
| Axios | Підготовка взаємодії з серверним API |
| ESLint | Статичний аналіз коду |
| Prettier | Автоматичне форматування коду |

Клієнтська частина розроблялася як окремий проєкт у каталозі `frontend` наявного репозиторію `health-monitoring`.

## 2. Створення та налаштування проєкту

Для створення клієнтської частини було використано Vite із шаблоном React та TypeScript.

Проєкт було створено в каталозі `frontend` репозиторію. Після встановлення залежностей було перевірено запуск сервера розробки та відображення початкової сторінки.

Для стилізації було встановлено Tailwind CSS із використанням офіційного Vite-плагіна `@tailwindcss/vite`. Плагін було додано до конфігурації `vite.config.ts`, а в основному CSS-файлі підключено Tailwind через директиву імпорту.

Також було налаштовано ESLint та Prettier. ESLint використовується для перевірки коду на помилки та недотримання правил розробки, а Prettier — для автоматичного форматування файлів.

У `package.json` було додано команди:

- `npm run dev` — запуск сервера розробки;
- `npm run build` — перевірка TypeScript та створення production-збірки;
- `npm run lint` — перевірка коду ESLint;
- `npm run format` — форматування файлів;
- `npm run preview` — локальний перегляд production-збірки.

## 4. Реалізація повторно використовуваних компонентів

Було створено набір базових компонентів, які можна використовувати на різних сторінках застосунку.

### 4.1. Button

Компонент кнопки підтримує декілька варіантів оформлення: основний, додатковий та небезпечний. Також передбачено стан завантаження та блокування кнопки.

### 4.2. Input

Компонент поля введення підтримує стандартні властивості HTML input та необов'язковий текстовий підпис. Для оформлення використано стилі Tailwind CSS.

### 4.3. Card

Компонент картки призначений для групування інформації. Підтримує заголовок, довільний вміст та додаткові CSS-класи.

### 4.4. Badge

Компонент Badge використовується для відображення коротких статусів або категорій. Реалізовано варіанти оформлення для успішного стану, попередження, помилки та інформаційного повідомлення.

### 4.5. Loading

Компонент Loading відображає індикатор завантаження та текстове повідомлення. Його можна використовувати під час виконання асинхронних операцій.

## 5. Реалізація компонентів макета

Для формування єдиного вигляду сторінок було створено три основні компоненти.

**Header** містить назву застосунку, навігаційні посилання на головну сторінку та сторінку з інформацією про проєкт, а також кнопку перемикання теми.

**Footer** розміщує інформацію про призначення застосунку та посилання на репозиторій GitHub.

**Layout** об'єднує Header, основну область вмісту та Footer. Для відображення вкладених сторінок використовується компонент `Outlet` з React Router.

Для забезпечення адаптивності застосовано класи Tailwind CSS із контрольними точками для різних розмірів екранів.

## 6. Реалізація сторінок та маршрутизації

Для навігації між сторінками було підключено React Router.

У застосунку реалізовано такі маршрути:

| Маршрут | Компонент | Призначення |
|---|---|---|
| `/` | HomePage | Головна сторінка |
| `/about` | AboutPage | Інформація про проєкт |
| `*` | NotFoundPage | Сторінка для невідомих маршрутів |

На головній сторінці розміщено назву системи, короткий опис її призначення та картки з основними напрямами функціональності: фізична активність, моніторинг здоров'я та аналіз даних.

На сторінці About наведено опис призначення системи та перелік використаних технологій.

Сторінка NotFoundPage відображається під час переходу за адресою, для якої не визначено окремого маршруту. Вона містить повідомлення про помилку та кнопку повернення на головну сторінку.

## 7. Налаштування взаємодії з API

Для підготовки взаємодії клієнтської частини із сервером було створено сервіс `src/services/api.ts` на основі Axios.

Під час створення екземпляра Axios налаштовуються:

- базова адреса API;
- заголовок `Content-Type`;
- перехоплювач запитів;
- перехоплювач відповідей.

У перехоплювачі запитів перевіряється наявність access token у локальному сховищі браузера. Якщо токен існує, він додається до заголовка `Authorization` у форматі Bearer.

У перехоплювачі відповідей обробляється HTTP-статус 401. У такому випадку з локального сховища видаляється збережений access token.

Для налаштування адрес API створено файли змінних середовища:

- `.env.development` — адреса локального сервера;
- `.env.production` — адреса розгорнутого сервера;
- `.env.example` — приклад необхідних змінних середовища.

Завдяки цьому адресу API можна змінювати залежно від середовища без редагування вихідного коду.

На цьому етапі створено інфраструктуру для HTTP-запитів, але повноцінне завантаження та відображення даних активностей у користувацькому інтерфейсі ще не реалізовано.

## 8. Типізація даних

Для забезпечення типобезпечної роботи з даними було створено окремі TypeScript-інтерфейси.

У `types/api.ts` визначено структури загальної відповіді API та відповіді з пагінацією.

У `types/activity.ts` описано структуру фізичної активності та дані, необхідні для її створення.

У `types/user.ts` описано структуру користувача.

Для ідентифікаторів використано тип `string`, оскільки серверна частина проєкту використовує UUID.

Окремий файл `types/env.d.ts` містить типи змінних середовища Vite, що дозволяє перевіряти їх використання засобами TypeScript.

## 9. Обробка помилок

Для перехоплення помилок рендерингу React-компонентів було реалізовано компонент `ErrorBoundary`.

Він побудований на основі класового компонента React та використовує методи:

- `getDerivedStateFromError` — для оновлення стану після виникнення помилки;
- `componentDidCatch` — для фіксації інформації про помилку.

Якщо під час рендерингу дочірніх компонентів виникає помилка, замість основного вмісту відображається повідомлення про проблему та кнопка перезавантаження сторінки.

Error Boundary підключено до основної області вмісту компонента Layout.

## 10. Реалізація теми оформлення

Для підтримки світлої та темної тем було створено користувацький React hook `useTheme`.

Він забезпечує:

- визначення початкової теми відповідно до системних налаштувань браузера;
- збереження вибраної теми в `localStorage`;
- перемикання між світлою та темною темами;
- застосування CSS-класу `dark` до кореневого HTML-елемента.

Для Tailwind CSS налаштовано спеціальний варіант `dark`, який дозволяє застосовувати відповідні стилі залежно від наявності класу `dark`.

Перемикач теми розміщено в компоненті Header.

## 11. Допоміжні функції

У каталозі `src/utils` реалізовано функції форматування даних.

`formatDate` призначена для форматування дат відповідно до української локалі за допомогою `Intl.DateTimeFormat`.

`formatNumber` використовує `Intl.NumberFormat` для форматування числових значень відповідно до українських регіональних налаштувань.

Ці функції можуть повторно використовуватися в різних частинах клієнтського застосунку.

Після реалізації основних компонентів було проведено перевірку роботи застосунку.

Для перевірки форматування виконано команду:

```bash
npm run format
```

Prettier успішно обробив файли вихідного коду. Повторне форматування не потребувалося, що підтверджено повідомленнями `unchanged`.

### 12.2. Перевірка ESLint

Для перевірки коду виконано:


Команда завершилася без повідомлень про помилки. Це підтверджує успішне проходження статичного аналізу коду.

## 13. Результати роботи

У результаті виконання лабораторної роботи створено клієнтську частину вебзастосунку Health Monitoring на основі React та TypeScript.

Було налаштовано середовище розробки, реалізовано структуру каталогів, повторно використовувані компоненти, основні сторінки, маршрутизацію, адаптивну стилізацію та перемикання тем оформлення.

Також підготовлено базову інфраструктуру для взаємодії із серверним API, типізацію даних, обробку помилок та допоміжні функції.

Коректність вихідного коду підтверджено успішним виконанням Prettier, ESLint та production-збірки Vite.

## Висновок

Під час виконання лабораторної роботи було створено основу клієнтської частини системи моніторингу фізичної активності та показників здоров'я з використанням React, TypeScript та Vite.

Було отримано практичні навички організації структури React-проєкту, створення повторно використовуваних компонентів, налаштування маршрутизації, роботи з Tailwind CSS, використання Axios та типізації даних.

Окрему увагу приділено адаптивності інтерфейсу, перемиканню тем оформлення, обробці помилок та інструментам контролю якості коду.

Усі реалізовані компоненти успішно пройшли перевірку ESLint, а production-збірка була створена без помилок. Таким чином, поставленої мети лабораторної роботи досягнуто, а створена клієнтська частина може бути використана як основа для подальшого розвитку повноцінного full-stack вебзастосунку.
