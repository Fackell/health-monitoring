# Звіт
## до лабораторної роботи №3
### «Взаємодія в реальному часі та фіналізація серверної частини»

**Тема:** Взаємодія в реальному часі та фіналізація серверної частини.

**Мета роботи:** Здобути практичні навички впровадження обміну даними в реальному часі у вебзастосунки з використанням WebSocket, оптимізувати роботу з базою даних, провести тестування серверного застосунку та розгорнути його на хостингу.

## 1. Використані технології

У межах роботи використовувалися Node.js, Express.js, Socket.IO, PostgreSQL, Prisma ORM та JWT. Для автоматизованого тестування застосовано Node.js Test Runner і Socket.IO Client. Сервер розгорнуто на Render, а база даних розміщена на Neon.

## 2. Інтеграція Socket.IO

До Express-застосунку інтегровано Socket.IO. Для цього створено HTTP-сервер на основі Express-застосунку та ініціалізовано Socket.IO на цьому сервері.

Реалізовано:
- автентифікацію WebSocket-підключень за допомогою access JWT;
- відхилення підключень із відсутнім або недійсним токеном;
- автоматичне приєднання автентифікованого користувача до персональної кімнати `user:<userId>`;
- події створення, оновлення та видалення фізичних активностей.

Для клієнтів передбачено події `activity:created`, `activity:updated` та `activity:deleted`. Події надсилаються до персональної кімнати відповідного користувача.

## 3. Оптимізація бази даних

Для сутності Activity додано складені індекси:

- `@@index([userId, startedAt])`;
- `@@index([userId, type, startedAt])`.

Індекси орієнтовані на запити, які фільтрують активності користувача за датою та типом і використовують сортування за часом початку.

Створено міграцію `20261119192544_add_activity_indexes` та застосовано її до бази даних.

## 4. Тестування

Для перевірки реалізованої функціональності створено автоматичні тести. Останній локальний запуск `npm test` завершився успішно: **5 тестів пройшли**.

Перевірено:
- відхилення реєстрації з порожніми даними;
- відхилення реєстрації з некоректною електронною адресою;
- відхилення входу без пароля;
- наявність захисних HTTP-заголовків Helmet;
- JWT-авторизацію Socket.IO та доставку події до персональної кімнати.

## 5. Розгортання застосунку

Серверну частину розгорнуто на платформі Render:

**Production URL:** https://health-monitoring-grk9.onrender.com

**Swagger UI:** https://health-monitoring-grk9.onrender.com/api-docs

**Health endpoint:** https://health-monitoring-grk9.onrender.com/api/health

Для зберігання даних використовується PostgreSQL у Neon. Під час розгортання налаштовано змінні середовища, команду встановлення залежностей, генерацію Prisma Client та застосування міграцій через `prisma migrate deploy`.

У production перевірено:
- доступність health endpoint;
- відкриття Swagger UI;
- реєстрацію нового користувача;
- вхід користувача;
- встановлення Socket.IO-з'єднання з передаванням JWT.

Під час перевірки Socket.IO сервер успішно прийняв автентифіковане підключення.

## 6. Документація

Створено README з описом проєкту, технологій, локального запуску, змінних середовища та розгортання. Окремо підготовлено документацію WebSocket API з описом автентифікації, кімнат і подій активностей.

## 7. Обмеження реалізації

У межах виконаної роботи реалізовано базову взаємодію в реальному часі для сутності Activity та вибрані елементи наступного рівня складності — JWT-автентифікацію WebSocket і персональні кімнати.

Не реалізовано збереження історії WebSocket-подій, відновлення пропущених повідомлень, онлайн-статуси користувачів, окрему модель сповіщень із пріоритетами, Redis-адаптер, кешування Redis та окреме обмеження частоти WebSocket-подій.

Файли, завантажені на локальну файлову систему Render, не слід вважати постійними без підключення зовнішнього сховища або постійного диска.

## 8. Висновок

Під час лабораторної роботи інтегровано Socket.IO у серверний застосунок, реалізовано JWT-автентифікацію WebSocket-з'єднань, персональні кімнати користувачів та передачу подій CRUD-операцій з активностями в реальному часі. Для оптимізації роботи PostgreSQL додано складені індекси для сутності Activity.

Проведено локальне автоматизоване тестування, перевірено основні production-функції та успішно розгорнуто серверну частину на Render із базою даних Neon. Підготовлено README та окрему документацію WebSocket API.
